# CeraUI Backend — Agent Routing

Parent: [workspace rules](https://github.com/CERALIVE/ceralive/blob/master/AGENTS.md); [CeraUI rules](../../AGENTS.md).

## ROLE
Bun/TypeScript device HTTP + WebSocket control plane. Serves the frontend,
exposes oRPC, and drives cerastream and the SRTLA sender through their bindings.
The engine owns capture identity; the backend preserves and projects it.

## STRUCTURE
- `src/` — entrypoint, domain modules, RPC, helpers, mocks and tests.
- `scripts/` — backend guards and bench harnesses.
- `docs/` — preserved backend subsystem contracts.

## COMMANDS
From the checkout root: `bun run --filter backend check`, `bun run lint`,
`bun run --filter backend test`, `bun run build:backend`.
Full PR gate: `bun run test`, `bun run test:e2e`, `bun run check:tech-debt`,
`bun run build` (see parent rules and CI; reader sweep precedes the gate).

## HARD RULES
- The backend preload owns a per-file OTA streaming sentinel before production imports; never share `/run/ceralive/streaming` between test files. Retained/unknown evidence tests must arrange it explicitly; inherited markers are not test cleanup targets. Contract: `docs/agents/dev-mock-seams.md`.
- Capable APT diagnostics scan whole normalized text before redaction/truncation; marked records own every subsequent continuation. Dedupe uses full sanitized SHA256 identity, not the 500-unit display or raw credentials. Contract: `docs/agents/software-update-check-contract.md`.
- Plain Bun transport fixture children require schema-valid setup metadata, including explicit hardware; partial setup defaults are not a complete document. Both netns clients share fixture preparation, tested without privileges. Contract: `docs/agents/dev-mock-seams.md`.
- Journal removal succeeds only after unlink/ENOENT and parent fsync; propagate every other unlink error into incomplete replay, never pre-count retirement. Failed directory acknowledgement is owned for fsync-only retry, not repeated deletion or empty readback. Operator archive failure is typed and its acknowledged decision can be explicitly retired again. Every slot writer/deleter holds the key's mutation lease through its awaited unlink/fsync/refresh; operators read eligibility first and never wait on armed/executing; the RPC transport passes no abort signal, so a waiting retirement survives client disconnect/timeout. Confirmed leases commit existing `completed` before removal, release in finally, and retain attempt-bound failed-write bookkeeping under the same owner after a second I/O fault. Runtime verification may settle submitted bookkeeping but never rolls hardware back. Check cancellation after every attempt outcome; an already-aborted sleep arms nothing. Contracts: UPDATE-RECOVERY.md and the modem safety contract.
- Replay fence/read failures mean an incomplete pass, never a blocked verdict: retain REPLAY under the boot barrier, including fencing before an absent action read is skipped. Retry rereads disk and already-restored hardware; waits cap at 60 s and shutdown cancels, with no timeout-open under continuous churn. Benign overlapping commits can raise recovery on healthy storage. The global revision can make acknowledge/decommission/rebaseline return `not_blocked` on an unrelated commit/read fault; archiveAcknowledged can reject after durable removal when both refresh fences fail. A process exit after config replacement but before strict load can lose its reset notice entirely; the next boot loads first-run settings with no notice and retains the damaged copy. Contracts: UPDATE-RECOVERY.md and the modem safety contract.
- Preservation resumes at both boundaries: verify/reacknowledge a published digest copy before temp allocation; retain failed temp cleanup by nonce and pinned inode until retry succeeds, never delete published evidence. Retain a config reset's archive identity through failed reloads; announce it once after the first successful strict load in that boot lifetime. Journal commits/removals/read faults share one process-local revision: recheck before block publication and barrier completion, with no writer in flight. Remember raises during a pass; invalidated passes retain capped/cancellable retry ownership. Genuine absence and concurrent slot deletion are not damage. Runtime verification never repeats hardware. Contracts: CONFIG_PERSISTENCE.md and UPDATE-RECOVERY.md.
- Helper settlement uses none/started/unknown, not missing-handle/errno inference. Preserve the fixed Bun socketpair/fcntl/posix_spawn pre-exec proof. A checked Bash launcher must record $$ before helper exec (write failure exits125). Handle-less recovery reads the retained FD of its exclusive UUID file under root0700 /run/ceralive/addon-launch, validates bounded integer2..2147483647, then uses the same group-plus-unit proof, never a census. Normal handles never read it. Empty pidfd identity clears only under the fixed-Bun1.4.2 post-exec-reaping assumption; unknown-tag absence gets cancellable100/200/400ms re-reads, not independent death proof. Invalid/unreadable identity stays UNKNOWN; cleanup follows no dispatch/group retirement only. First-use stale sweep must precede current active files. Reaudit runtime/options changes. Cancellation/retirement fences first observations. Other callers/D249/D257 stay unchanged; both-board Bash/run-directory/file/pidfd drills remain owed, and forcing installed pidfd failure requires privilege. Contract: `../../docs/agents/add-on-subsystem.md`.
- Every bounded runner shares `bounded-spawn.ts` termination ordering: our timeout/abort before exit is failure even when TERM exits zero. Keep genuine zero observed before termination; preserve partial output and RunTimeoutError/RunAbortError. Add-on validation timeout auto-disables with `addon_validation_failed`, never enables.
- OS-stage refusal logs retain closed first-failure provenance separately from final settlement/startup proof. Context is bounded, message/path/PID/argv-free and in-memory/log-only; never persist it or use it as authority. Contract: UPDATE-RECOVERY.md → Self-describing stage refusals.
- Stored authority uses the shared anchored/no-follow/nonblocking bounded read and fatal UTF-8/raw duplicate-member boundary. Unit properties use the shared strict parser and not-found consistency rule. Diagnostic getter faults must never replace the original throw. Contract: UPDATE-RECOVERY.md → Strict stored authority.
- Add-on descriptor authority requires exact `<id>.json` filename/embedded-id equality before returning data. Misplaced records take existing invalid-descriptor refusals, log their slot once per failed read/pass and preserve bytes; never repair or use the embedded id under another id's intent/lock. Healthy bound siblings remain serviceable. Contract: `../../docs/agents/add-on-subsystem.md` → Descriptor slot identity.
- Unknown capability authority is never legacy: only genuine absence or a valid declaration selects an install regime. Refuse refresh/discovery/install with existing typed reasons, preserve bytes and re-read after repair. Terminal package completion needs present whole-string bounded exit properties and coherent lifecycle; unknown never grants cleanup. Repeated identity sections/keys refuse, never first-match. Contract: UPDATE-RECOVERY.md → Capability regime and terminal package evidence.
- Only OS metadata permits the exact `/etc/os-release` link to `/usr/lib/os-release`; its fixed target still uses the strict reader. Present invalid idle evidence is `activity-unknown`, never cached idle. Mixed config safety fields, setup, modem journal/FCC opt-in, auth tokens, add-on descriptors and shaper ownership cannot use preference defaults as authority. Contract: UPDATE-RECOVERY.md → Metadata and idle boundaries.
- Unknown optional-record reads never seed a write; only explicit password-change/revoke-all may reset unavailable token membership. Config boot, modem recovery and per-operation token/FCC reads own retries. Journal inventories skip concurrent deletion, never parse damage; shutdown disarms retry. Shaper work starts pending and clears only after successful apply. Token revocation intent filters every read/save until persistence succeeds; the next auth operation retries once, shutdown stops retry, and damaged/unavailable remembered login stays temporary (D209). Intent is not restart-durable after a failed save. Required `setup.json` retries transient reads ~3 s then exits typed; damage aborts. `Restart=always` is rate-limited: absent explicit pacing/start-limit settings, fast exits can hit `start-limit-hit` and stay failed. Restart policy is an owner/image decision. Damage archives retain exact bytes with bounded temp cleanup. PRE-EXISTING OWNER DECISION: config loss without salvageable `password_hash` resets to first run and ANY LAN client can claim the device, as at 23bcf379. Contract: `../../docs/UPDATE-RECOVERY.md` → Unknown optional-record reads: no boot abort, no wedge, no write baseline.
- Stream admission is cancellable before the D8 await. Every Stop caller reports intent before joining/parking cleanup; operator intent requests restoration disarm and immediately revokes pending commitment and delayed arming authority. Engine-loss/reconfigure retain intent. Cancellation waits for parked cleanup; it must not race the engine mutex. Operator cause survives release. The import-free intent epoch fences pre-generation waits, commitment/hooks and restoration preparation/settlement; it never proves idle. OTA protection survives parked/failed/unknown stops until confirmed idle/cleanup. Subprocess termination-induced zero exits never become success or positive CLI evidence.
- Stream-session projection is atomic with its ownership/transition guard. Submitted cleanup stays single-flight after caller timeout; reconciliation cannot admit a launch through it. Unknown launch cleanup/socket loss retains generation, OTA protection and last confirmed live status. Contract: `../../docs/START-LIFECYCLE.md` → Session ownership state machine; bounded subprocess drainage/retirement lives in `src/helpers/bounded-spawn.ts`.
- Profile reconnect captures operator intent before its machine Stop await and rechecks before replacement Start; a joining operator cancels the restart flight.
- Silence is not new idle evidence. Absent sentinel/no required protection/no pending launch is an unprotected baseline at boot AND after confirmed cleanup, regardless of generation; silent probes gate only in flight. Protected/adopted/uncertain sessions remain gated. Update/disruptive consumers use leaf `streamLiveness()` through the synchronous system adapter: initial reconciliation, positive legacy live and the owner's published lifecycle may only withhold idle; no independent sentinel read. Never import the orchestrator re-export. Failed sentinel clearance stays UNKNOWN and retries on affirmative evidence; failed writes retry on current streaming status. Cancelled starts retain rollback certainty and the cancelling Stop acknowledgement/cause. Probes do not invalidate session subscriptions unless adopting a client. Operator Stop can confirm an unowned engine; reconciliation never Stops UNKNOWN. Contract: `docs/agents/streaming-engine-seam.md`.
- OS-stage enumerated process reads share scope-explicit ENOENT/ESRCH absence; never invent identity or keep a cached vanished member. Other errors/malformed identity stay unknown. ESRCH never proves cgroup, marker or block-resource absence; guardian disappearance requires fresh proof. Successful empty content is not a disappearance errno; preserve and report its content-classification limits in UPDATE-RECOVERY.md.
- The projection is what reaches the wire: seed lifecycle state from the owner at composition before hydration, without broadcast or engine-query wait. Retained protection seeds reconciling; absent/unprotected boot seeds idle. The first safe transition still broadcasts, including same-state reconciliation. Runtime evidence is bound to its producing client/epoch and invalidated at new Start/acquisition/commit; old idle cannot establish new-session idle. Preserve producer identity and schema.
- Update outcomes need their own positive evidence: package success is not restart completion; activation-request submission is not a verified running OS. Present unreadable/invalid channel overrides refuse discovery, never fall back. Transport cost/history unknown stays unknown. See `../../docs/DEVICE-UPDATES.md` → Outcome evidence.
- Flow-sticky shared-client steering affects only forwarded client-zone traffic; preserve physical-identity marks and established flows.
- Streaming-first uplink shaping caps only shared clients; local stream egress stays uncapped. Foreign roots fail closed.
- The two NAT layers are watched, never arbitrated: diagnostics are read-only, tri-state, and never gate streaming or mutate either layer.
- Host-uplink family success survives joined sibling faults; unsuccessful unbound faults stay UNKNOWN and cannot abort candidate election or authorize release. See `../../docs/HOST-UPLINK-ELECTION.md`.
- Disruptive effects use the final synchronous gate and `disruptive-action-reservation.ts` exclusion. Every uncertain hold has an evidence resolver, never timer release: `withServiceReservation(fn, scope, probe?)` in `disruptive-service-reservation.ts` releases service depth only on positive completion/failure, polling the actual operation-owned unit/job with capped cancellable backoff. Timed arm terminal success retains shutdown. Same-power-action explicit retry keeps ALL current stream/update fences; failed retry preserves the earlier hold. Console power is last resort. Legacy completion reboot defers rather than discards. D8 refuses starts while held; no automatic Stop. In-process state resets on restart, not durable exclusion. Contract/state table: `../../docs/START-LIFECYCLE.md` → Disruptive-action gate.
- Add-on seam API: `reserveDisruptiveAction(decision, "service", owner: symbol)` and `getDisruptiveActionDecision({ heldBy: owner })`; only the same ACTIVE lifetime re-enters, nested depths settle independently and the last release opens admission. Released/uncertain owners refuse, including late timer descendants. `withServiceReservation` scope supplies `unit`, synchronous `decision`, optional `owner`; custom probes must positively settle the actual helper/job, never borrow an unrelated idle unit. The liveness accessor stays synchronous/side-effect-free and may only become more restrictive. Update busy-source registration is a runtime module-evaluation side effect, not initialized-runtime evidence; its unregistered default refuses.
- Disruptive mutations use the single `disruptive-action-gate.ts` through its public runtime adapter, never a copied live-flag predicate. Preserve refusal tokens before intent/effects and re-read after awaited preparation before privileged submission. Canonical action inventory and residuals: `../../docs/START-LIFECYCLE.md` → Disruptive-action gate.
- Add-on mutation/operation tokens expire in finally; recurring kiosk polling stays outside those contexts. The sysext seam owns reentrant service depth. Helper mutations use ordinary checked `setsid -w --` spawning (no sudo/detached/PTY/-f), root-only, fixed PATH/locale without inherited shell/tool overrides. Success and effectful exit 1 require actual child exit, valid owned PGID > 1 and ESRCH from signal-zero on the NEGATIVE group, latched before descriptor-unit settlement. Other errno stays UNKNOWN; zombies over-hold, never census-skip. Collector signals only the child and preserves partial output/actual 137/143. Generic outer census remains separate; manager unit tails gain no group ownership. Session escapes trigger scope replacement; PID-1/daemon work, manager Reload and killed-client unacknowledged delegation are not contained. Restart clears local holds, not completion proof; KillMode=mixed still reaches the service cgroup. No service supersession or total preparation deadline (D249). Pre-submission CONTROL refusal may leave shutdown over a never-executed arm unit; only existing same-action reboot/restart escape, no reason whitelist (D257). Installed behavior needs BOTH-board drills. Contract: `../../docs/agents/add-on-subsystem.md`.
- Modem roster: exact triplets; RNDIS e0/01/03 admits; e0/01/01, e0/01/04 veto; ID_MM_DEVICE_IGNORE=1 excludes; weak retires, strong stays undriveable.
- Update roster uses exact package names, never prefixes; unknown names default to platform. Install only actionable entries.
- OS stage extras defer only under bounded fresh proof, never a helper whitelist or cached recovery grant. Retain CONTROL/private/guardian authority and the settled pair's absolute monotonic deadline through retry/release; bound every proof await and invalidate expired captures. Final observation follows awaited preparation; dispatch has only synchronous checks afterward. Positive CLI exit survives cancellation/output drainage and exact runtime/D8 settlement preserves terminal unpublished-success unsafe, never restage. Startup/orphan use the same strict proof seam. Contract and remaining board gates: `../../docs/UPDATE-RECOVERY.md`.
- OS receipt cleanup requires persisted CONTROL authority, read-time file identity and positive installed-image binding; legacy/unknown evidence KEEP. Cooperative production writers hold CONTROL: commitStagedManifest via stage callback, rebindStagedReceipt via runtime reconciliation, retry via leased stage entry. Low-level saveStagedManifest requires no lease. Root/image helper --arm/--stop uses its own activation flock, not CONTROL; ExecStop must stay CONTROL-independent. Re-probe the marker after final authority without claiming privileged exclusion. Cache successful tombstone acknowledgement by full identity for this process only; failure/change/restart requires retry. Unlaunched settlement may ignore only an unchanged recorded baseline, never launched/new/unknown outcomes. See the update-orchestrator contract and UPDATE-RECOVERY.md for accepted D154 residuals and bench rollback compatibility.
- Every modem mutation uses the identity-resolved lifecycle lease; connectivity mutations arm the durable journal before writing; retain rollback.
- A journal record is valid only in `sha256(record.stableKey).json`: direct reads bind to the requested key, inventories to the exact filename. A misplaced record is a damaged slot (barrier raised, bytes kept, never replayed, retired or treated as absent); retirements refuse with `state_mismatch` any record naming a key other than their lease's.
- OS staging's observer-internal final census follows optional diagnostics; drift returns no snapshot. Only its closed census-drift diagnostic permits bounded re-observation under the same authority/deadline, and only with valid non-census predicates; concurrent Operation/health/boot/slot faults stay terminal. Positive CLI success vetoes transfer retry. Carry one remaining deadline through outer ports and physical release, fencing late mutation callbacks. The non-atomic dispatch gap and inherited size exceptions are explicit in UPDATE-RECOVERY.md; never claim uniform size compliance or test type coverage from the normal backend check.
- Retained-pin drainage uses the reconciler's active deadline and CONTROL fence, not the expired producer deadline. Retained capture is read-only; ownership preparation precedes the final physical observation and synchronous release checks.
- OS routing teardown and reconciliation sweep pass their remaining budget through every command submission. Quiet startup's no-job/no-directory fallback uses one 10-second CONTROL/producer-fenced budget, checked again before admission opens. Timeout retains unresolved ownership; no late query can initiate a deletion or flush after its generation/CONTROL fence closes. Ordinary routing callers keep their existing teardown and per-command timeout semantics.
- Orphan unit/token/file inspection lives in `os-stage-orphan-inspection.ts`; `os-stage-orphan.ts` owns its bounded settlement lifetime. Keep both under the module-size ceiling.
- Capability feature gates are default-absent; absent/false is inert. Mutations use the shared gate helper and modem safety contract.
- Live capture and audio devices are never silently dropped: emit honest unavailable entries when a pipeline or route cannot honor them.
