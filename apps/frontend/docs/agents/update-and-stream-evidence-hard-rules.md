## HARD RULES

- Call initSubscriptions() before mount; its handlers feed every subscription getter. Never create a second socket consumer.
- Import wire contracts from @ceraui/rpc and producer exports; never shadow a wire type or fabricate an advertised mode.
- Unknown, absent and explicit unsupported are distinct states; render typed refusals through keyed localized copy, never raw tokens.
- SSH start/stop/persist maps streaming, unknown-liveness and update/pending-disruption refusal tokens to `notifications.disruptiveActionRefused`; preserve separate operation keys and pessimistic device state. No client timer grants backend permission.
- Update installation, restart and activation are separate conclusions. Use the update evidence contract: no restart from package success, no historical connection absence from null, no failed reachability or metered cost from unknown, and a terminal install result releases the takeover.
- Draw stream conclusions from current-link receipt AND, for pulls, dispatch after the claim/newest STREAM-FACT observation (`is_streaming`, `stream_lifecycle`, unknown fields fail closed as one group). Fields unrelated to stream settlement still gate other decisions. Merge them independently, preserving newer overlapping pushes/reads; stream-superseded pulls allow at most one fresh read, never settlement from their stream fields. Exhausted current Start recovery retains generation-owned UNKNOWN with the existing band's operator Stop until positive admissible settlement or its owner's acknowledged Stop. The latest Stop owner's acknowledgement settles its captured, still-current starting attempt before OR after exhaustion; retain Stop-owner and Start-generation fences, never require recovery-record presence. Operation confirmation still needs post-press idle lifecycle evidence. Fence watchdog effects to their action lifetime; no automatic Stop. Keep unresolved-action ownership, full-snapshot lifecycle replacement, partial-push merging and field dedupe (START-LIFECYCLE, Contract 32).
- Add-on/kiosk disruptive refusals reuse `notifications.disruptiveActionRefused`, revert controls and never claim emulated-mode unavailability. Admission inventory: `../../docs/START-LIFECYCLE.md` → Disruptive-action gate.
- Stop acknowledgement authority is latest-owner identity plus captured Start generation/state, whether or not admissible settlement already closed the claim. Idle confirms the Stop operation but does not by itself revoke acknowledged Start before recovery; failed Stop and pre-record boolean false do not revoke it. Post-record admissible evidence still clears UNKNOWN; the band's Stop is the escape. The 36-cell `LiveView.real-socket-stop.test.ts` permutation matrix owns this contract; no automatic Stops.
- Preserve authentication ownership, lazy dialog loading and bounded persistent notifications; read the routed subsystem before editing.
- A thrown Start error proves idle only when it is the existing NotSentError. Timeout/reset/handler errors retain the lost-reply generation and 90-second watchdog; negative Start results keep their typed failure handling. Preserve the original 36 S/R/E cells and the added timeout dimension (START-LIFECYCLE, FIX-17-F11); no automatic Stop.
- Use the Paraglide facade; namespace activation owns boot/destination loading. Never import /eager in app code.
- Never hand-edit CLI-managed shadcn primitives; retain accessibility, focus and clipped-disclosure behavior.
- Federation builds/signatures/publish must agree with the hosted bundle graph and support window; read all three federation contracts.
